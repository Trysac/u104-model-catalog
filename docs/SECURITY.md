# Security Notes\n\n## Threat Model\n\n### Defended\n\n- **Hostile Inputs**: The library strictly validates all input (types, formats, integer ranges, regex for IDs and prices) before processing. It rejects malformed JSON and files exceeding `max_bytes`.\n- **Injection**: No dynamic execution (`eval`/`exec`) is used. Data is parsed as a static mapping.\n- **Information Leakage**: The library contains no network I/O and reads no system secrets; it is a passive data parser.\n\n### Not Defended\n\n- **Source Integrity**: This library treats the provided catalog file as trusted input. If the underlying JSON file is maliciously modified, the library will return malicious data. Users must verify the integrity and source of their catalog files using VCS (e.g., git commit signing).
