# model-catalog\n\nProblem: LLM limits and prices change frequently. Hard-coding them into codebases results in cost estimation errors and stale routing. This library maintains a single, versioned, validated JSON catalog with documented source URLs, allowing reproducible historical lookups.\n\n## Installation\n\n```bash\npip install model-catalog\n```\n\n## Usage\n\n```python\nfrom datetime import date\nfrom decimal import Decimal\nfrom model_catalog import load_catalog\n\ncat = load_catalog("catalog.json")\n# Lookup model at a specific point in time\nm = cat.get("m-a", at=date(2026, 6, 1))\nprint(f"{m.id}: {m.input_per_mtok} per Mtok")\n\n# Query with filters\nmodels = cat.query(capabilities=["vision"], min_context=100_000)\n```\n\n## Public API Summary\n\n- `load_catalog(source: str | os.PathLike | Mapping, *, max_bytes: int = 1_048_576) -> Catalog`: Parses a JSON source. Raises `CatalogError(code)` for invalid structures or if the size exceeds `max_bytes`.\n- `Catalog.get(model_id: str, *, at: date | None = None) -> Model`: Retrieves model specs. Uses the latest entry if `at` is None, or the latest entry valid on the provided date.\n- `Catalog.query(...) -> list[Model]`: Returns matching models sorted by input price and ID. Filtering parameters include `provider`, `min_context`, `capabilities`, `max_input_price`, and `at`.\n- `Model`: A frozen dataclass containing `id`, `provider`, `context_window`, `max_output`, `input_per_mtok`, `output_per_mtok`, `capabilities`, `valid_from`, and `source`.\n\n## Why not provider SDK constants or LiteLLM?\n\nExisting solutions rely on hard-coded internal maps or dynamic network fetching. `model-catalog` provides a versioned, point-in-time snapshot that you store, control, and audit within your own repository, ensuring your production logic is always deterministic.\n\nSee [docs/SECURITY.md](docs/SECURITY.md).
